## 核心诊断：为什么参数调优到了天花板

过去三轮消融实验揭示了一个关键规律：

```
基线 +98.23%（高收益、高风险）
     ↓ 风控优化
v1.1 +48.66%（低回撤、低收益）
     ↓ 进攻性调优
FINAL +43.50%（更低收益）← 调优反向恶化
```

这不是参数没调好，而是**当前策略存在一个结构性约束**：

```
平均盈利 $24 vs 平均亏损 $48 → 盈亏比 0.50

这意味着：
  每赢一笔，只赚 $24
  每输一笔，亏  $48（是盈利的 2 倍）

要达到 +200%，需要净利润 $20,000
在当前盈亏比下：需要 (742笔 × 80.7% × $24) - (742笔 × 19.3% × $48)
= $14,400 - $6,877 = $7,523（实际只有约 $5,900，接近回测值）

要把净利润推到 $20,000，要么交易数翻 3.4 倍，要么盈亏比翻 3.4 倍
两者都做不到——前者胜率会崩溃，后者需要止盈从 $24 提升到 $82
```

**结论**：0.50 的盈亏比是当前架构的核心瓶颈，不是杠杆问题、不是仓位问题。

## 第一部分：短期稳定目标（4~6周）

放弃 +200% 的单轮目标，转向**可持续复利**路径：

```
当前 v1.1: +48.66% / 30天
目标: +55%~65% / 30天（稳定可复利）

复利视角:
  +55%/月 × 12个月 = 年化 ~2,500%（理论值，实际有摩擦）
  +48%/月 × 3个月  = 初始资金 $10,000 → $31,558
  要达到 +200% 总收益，用 2 个月 +48% 即可
```

#### 修复 1：Runner 机制重建（最高优先级）

**问题来源**：Test-R1 的四级 TP 设计将第3级 reduce 从 0.20 提升至 0.30，同时第4级 close_ratio=1.0 强制全平，导致尾仓（runner）从 25% 压缩至 15%，且在 4% 处被硬切，截断了超额趋势利润。

**修复方案 A（推荐）：恢复原始3级结构，但优化第3级触发点**

```json
// 变更前（v1.1 原始）
"take_profit_pct_levels":        [0.008, 0.012, 0.020],
"take_profit_reduce_pct_levels": [0.25,  0.30,  0.20]
// runner = 25%，trailing stop 自由运行

// 变更后（修复版）
"take_profit_pct_levels":        [0.010, 0.015, 0.025],
"take_profit_reduce_pct_levels": [0.25,  0.30,  0.20]
// 将触发点整体上移 25%，让 runner 在更高位置开始
// runner 仍为 25%，trailing stop 从 2.5% 开始
```

**设计逻辑**：触发点上移意味着每一级止盈都在更有利的位置锁定，减少噪音平仓，同时 runner 的起点更高，trailing stop 效率更好。

**变更文件**：

```json
// config/trading_config_fund_flow.json
"take_profit_pct_levels": [0.010, 0.015, 0.025],
"take_profit_reduce_pct_levels": [0.25, 0.30, 0.20]
```

**验证标准**：

```
目标: 平均盈利从 $24 提升至 ≥ $28（+16%）
接受: profit_factor ≥ 2.15，win_rate 变化 ≤ ±0.5%
拒绝: 平均盈利 < $24（不如原始3级）
```

### 方向 A：趋势强度分级持仓系统

**核心思想**：当前策略对所有信号用同一套 TP 规则，但不同信号类型的趋势延续能力差异很大。

```
flip_bullish:    单笔均盈 $17.91（当前最高），说明反转后动量强
red_bar_growing: 单笔均盈 $6.93，趋势延续但幅度有限
```

如果 flip_bullish 使用更宽松的 TP（允许趋势运行更长），其平均盈利理论上可以从 $18 提升至 $25~$30。

**实现方案**：

```json
// 为不同信号类型设置独立的 TP 配置

    "trailing_stop_enabled": true,
```

**预期影响**：

### 方向 B：CVD 资金流信号引入

**背景**：当前 CVD 过滤器被禁用（`cvd_filter_config.enabled: false`）。CVD（累积成交量差值）是衡量主力资金真实流向的核心指标，在加密市场中与短期价格走势高度相关。

**消融数据支持**：

```
当前亏损 Top 10 中有 6/10 发生在 UTC 00:00-06:00
这些时段 CVD 往往显示资金流入方向与价格方向相反（假突破）
如果在入场前过滤 CVD 背离情况，预计可减少 15%~20% 的 intrabar 止损
```

**实现方案**：

```json
"cvd_filter_config": {
  "enabled": true,
  "session_reset": "daily_utc0",
  "lookback_15m": 3,
  "positive_delta_ratio_threshold": 0.05,  // 宽松版：5% 以上 CVD 净流入
  "apply_to_signals": ["flip_bearish", "flip_bullish"],  // 先只对翻转信号启用
  "veto_on_cvd_divergence": true   // CVD 与价格方向背离时否决入场
}
```

**分阶段启用**：先对翻转信号（flip）启用 CVD 过滤，验证有效后再扩展到全部信号类型。

**预期影响**：

```
intrabar 止损率从 76.8% 降至估算 65%~70%
flip 信号胜率从 72%~88% 进一步提升
全局胜率预估从 80.7% → 82%~83%
净收益增量: +5% ~ +8%
```

### 方向 C：多周期确认强化（减少假突破）

**背景**：当前最大的亏损根因仍是 `stop_loss_intrabar`（76.8% 的亏损），根本原因是在 K 线内被噪音触发，而不是真正的趋势反转。

**当前问题**：

```
入场逻辑：信号触发 → 立即 IOC 市价入场
问题：在 15M K线开盘后立即入场，此时 K线价格区间最不确定
```

**优化方案：等待 K 线内结构确认**

```python
# src/fund_flow/execution_router.py
# 新增入场等待逻辑（不改变信号生成，只改变执行时机）

def should_execute_entry(signal, current_bar_progress: float) -> bool:
    """
    current_bar_progress: 当前 K 线已经过去的比例（0.0~1.0）
    在 K 线前 20% 触发的信号等待到 30% 再入场
    目的：让价格先完成初始波动，再在相对稳定位置入场
    """
    if current_bar_progress < 0.20:
        # K 线刚开，等待价格方向确认
        return signal.score >= 0.92  # 只有极高分信号立即入场
    elif current_bar_progress < 0.40:
        return signal.score >= 0.85  # 正常分数信号等过 20% 再入场
    else:
        return True  # K 线后半段直接入场
```

**预期影响**：

```
减少 K 线开盘初期的假突破入场
intrabar 止损从 76.8% 降至估算 60%~65%
平均入场价格改善约 0.1%~0.15%
考虑当前 2% 止损，这意味着有效止损空间扩大 5%~7.5%
全局净收益增量: +4% ~ +7%
```

**代码改动**：仅改 `execution_router.py`，不改信号层，风险最低。

### 方向 D：动态仓位系统（替代固定 50% 目标仓位）

**背景**：当前仓位系统主要依赖 VWAP 评分分层，但忽略了**账户近期表现**对仓位的影响。

**核心思想**：在连续盈利期适度加仓，在连续亏损期自动收缩仓位，实现"顺风时赚更多，逆风时少亏损"。

```python
# 动态仓位乘数计算逻辑
def get_dynamic_position_multiplier(recent_trades: list) -> float:
    """
    基于近5笔交易的盈亏情况动态调整仓位
    """
    if len(recent_trades) < 3:
        return 1.0  # 数据不足，维持标准仓位

    recent_pnl = [t.pnl for t in recent_trades[-5:]]
    win_streak = sum(1 for p in recent_pnl if p > 0)
    loss_streak = sum(1 for p in recent_pnl if p < 0)

    if win_streak >= 4:
        return 1.15   # 近5笔4胜：仓位上调 15%
    elif win_streak >= 3:
        return 1.05   # 近5笔3胜：仓位上调 5%
    elif loss_streak >= 3:
        return 0.75   # 近5笔3负：仓位下调至 75%
    elif loss_streak >= 4:
        return 0.60   # 近5笔4负：仓位下调至 60%（触发 consecutive_loss 冷却前的保护）
    return 1.0
```

**配置开关**：

```json
"dynamic_position_config": {
  "enabled": true,
  "lookback_trades": 5,
  "win_streak_3_multiplier": 1.05,
  "win_streak_4_multiplier": 1.15,
  "loss_streak_3_multiplier": 0.75,
  "loss_streak_4_multiplier": 0.60,
  "max_multiplier": 1.20,
  "min_multiplier": 0.55
}
```

**注意**：该逻辑属于资金管理层，与信号层独立，是最安全的扩容方式。

## 第三部分：+200% 的真实路径

基于全部消融数据，+200% 需要以下三项同时成立：

```
条件 1: 盈亏比从 0.50 提升至 0.80
        → 方向 A（信号类型独立 TP）+ 方向 C（入场时机优化）
        → 平均盈利从 $24 → $32，平均亏损从 $48 → $42
        → 预计贡献: +35% ~ +50%

条件 2: 交易频率从 585 → 750+
        → 方向 B（CVD 信号引入新交易机会）
        → 预计贡献: +20% ~ +30%

条件 3: 顺风期动态加仓
        → 方向 D（动态仓位系统）
        → 在策略处于连盈状态时主动放大规模
        → 预计贡献: +15% ~ +25%
```

**综合估算**：

```
v1.1 基线:            +48.66%
+ 短期修复三项:       +59%    (+10%)
+ 方向A (信号TP分化): +72%    (+13%)
+ 方向B (CVD扩容):    +90%    (+18%)
+ 方向C (入场优化):   +108%   (+18%)
+ 方向D (动态仓位):   +130%   (+22%)
─────────────────────────────────
组合效应估算:         +160% ~ +200%
```

> 这个路径的时间跨度是 **6~10 周**，每步独立验证，不能跳过。
