## 三、关键发现与归因分析

### 3.1 收益下降归因

组合优化后收益从 +48.66% 降至 +43.50%（**净减 -5.16%**），主要原因：

**（1）四级TP导致平均盈利大幅缩水** (-$5.77/笔)

- 原始3级TP: 25%+30%+20% = 75% 在前3级平仓，**25% 留作 runner 使用 trailing stop**
- 新4级TP: 25%+30%+30% = 85% 在前3级平仓，**15% 在4%处全平**
- 关键问题：runner 比例从 25% 降至 15%，而 4% 硬止盈截断了部分超趋势利润
- 新第4级 close_ratio=1.0 意味着剩余仓位在 4% 处强制全平，消除了 trailing stop 捕捉超额趋势的能力
- 同时第3级 reduce_pct 从 0.2→0.30 也提前锁定了更多仓位，减少了 runner 规模

**（2）VWAP劣势仓位扩大增加亏损** (-$193)

- long_below_both 亏损从 -$152 扩大至 -$345（+127%）
- 47笔交易中胜率仅 70%，仓位从 55%→70% 使单笔亏损敞口增大
- 短期 gain 无法补偿这部分 loss

**（3）min_signal_score 提升过滤了部分低分盈利交易**

- 信号总数从基线未统计降至 600 笔（实际 +15 笔，因其他扩容项对冲）
- red_bar_growing 从 0.78→0.80 可能过滤了一些有效但分数在 0.78-0.80 区间的盈利信号

### 3.2 正面改善

| 改善项 | 详情 |
|--------|------|
| 胜率提升 | 80.7% → 82.5%（+1.8pp），信号质量略改善 |

| 回撤降低 | 4.87% → 4.29%，风控表现更优 |
| 平均亏损收窄 | -$48 → -$36.53，止损机制更紧 |
| flip_bearish 盈利 | 从 $0 恢复至 +$240，vwap门槛回调有效 |

### 3.3 stable_bull_continuation 未产生独立交易

启用 stable_bull_continuation 后，该信号类型未产生可识别的独立交易记录。可能原因：

- 需要同时满足 min_vwap_score≥0.12 + min_adx_1h≥30 + min_4h_bars≥2 的多重条件
- 其交易可能被归入 red_bar_growing 或其他信号类型中

## 四、与 +200% 目标的差距分析

### 4.1 数学现实确认

v1.1 基线结构：
```
净利润 ≈ $5,911（+48.66%）
目标净利润 = $20,000（+200%）
所需放大倍数 = 3.38x
```

当前组合结果：
```
净利润 ≈ $4,350（+43.50%）
距离目标缺口 = $15,650
```

### 4.2 瓶颈诊断

| 放大路径 | 预期杠杆 | 实际效果 | 结论 |
|---------|---------|---------|------|
| 杠杆放大 | 已至 5x 上限 | 平均杠杆已接近 max | 无法继续通过杠杆放大 |
| 信号扩容 | min_score 0.70→0.80 | 实际减少了低分交易 | 方向相反 |
| 盈亏比优化 | 四级TP | 平均盈利反降 23% | TP设计有缺陷 |
| 仓位解压 | VWAP劣势 70% | long_below_both 亏损翻倍 | 代价过大 |

**核心瓶颈**：当前策略架构下，收益放大与回撤控制存在根本性矛盾。任何单一维度的激进调整都会导致回撤上升或收益下降。

### 4.3 Test-R1（四级TP）设计缺陷分析

原始设计的 runner 机制（25% 尾仓 + trailing stop）实际上是一个有效的利润放大器：
- 在强趋势中，trailing stop 可以捕捉 4%~8%+ 的超额利润
- 强制在 4% 全平截断了这部分 alpha

**改进建议**：
```json
// 方案A: 保留 runner，仅微调前3级
"take_profit_pct_levels": [0.008, 0.012, 0.02],
"take_profit_reduce_pct_levels": [0.20, 0.30, 0.25]  // 尾仓 25%

// 方案B: 四级TP但第4级保留 runner 空间
"take_profit_pct_levels": [0.008, 0.012, 0.02, 0.04],
"take_profit_reduce_pct_levels": [0.20, 0.25, 0.25, 0.15]  // 第4级仅平 15%，留 15% runner

// 方案C: 降低第3级 reduce，增加 runner 比例
"take_profit_pct_levels": [0.008, 0.012, 0.02, 0.04],
"take_profit_reduce_pct_levels": [0.25, 0.30, 0.15, 0.10]  // 总平 80%，留 20% runner
```
