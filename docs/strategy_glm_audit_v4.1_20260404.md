## 第一部分：v4.0 结果的泛化性审计（GLM 严格分析）

### 1.1 样本量充分性检验

```
回测窗口:  30 天
总交易数:  591 笔
胜率样本:  591 × 82.5% ≈ 487 笔盈利，104 笔亏损

亏损样本仅 104 笔，对统计结论的可靠性影响：

  标准误差 = sqrt(p × (1-p) / n) = sqrt(0.175 × 0.825 / 591) ≈ 0.0156
  95% 置信区间: 82.5% ± 3.1% = [79.4%, 85.6%]

  → 当前 82.5% 胜率，真实值可能低至 79.4%
  → 在真实胜率 79.4% + 当前盈亏比 0.55 下：
     期望值 = 79.4% × $20.26 - 20.6% × $36.97 = $16.09 - $7.62 = $8.47
     对比当前实测: $16.59 - $7.55 = $9.04
     差距约 6.4%（不可忽视）
```

**结论**：30 天 / 591 笔的样本量对胜率的置信区间为 ±3%，**任何小于 5% 的收益改善都在统计噪声范围内**。

### 1.2 动态仓位系统的过拟合风险评估 ⚠️ 高风险

动态仓位贡献了 v4.0 中绝大部分的增量（+7.02%），但它有严重的过拟合嫌疑。

**问题一：回溯窗口与评估窗口重叠**

```
动态仓位逻辑: 用近5笔交易结果 → 调整当前仓位
回测验证方式: 同一段数据同时生成"近5笔结果"和"评估当前仓位效果"

这在逻辑上是合法的（无未来数据泄露），但存在：
  - 策略被同一段行情数据的局部模式所优化
  - 30天内的连赢/连亏序列是否具有可重复性，未经验证
```

**问题二：连赢/连亏序列的统计特征未验证**

```
动态仓位的前提假设: 
  "连赢4/5意味着市场与策略匹配，应该加仓"
  
这个假设需要验证：
  Q1: 在过去30天数据中，连赢4/5之后的第6笔交易，胜率是多少？
  Q2: 连赢序列的自相关性有多强？（如果是随机的，动态仓位只是噪声放大器）

如果连赢后的胜率 ≈ 平均胜率（82.5%），则动态仓位没有预测力，
+7.02% 的增量完全来自顺序效应（凑巧在连赢期加大了仓位）。
```

**验证脚本（必须运行再继续）**：

```python
# scripts/diagnostics/validate_dynamic_position_alpha.py
import pandas as pd
import numpy as np

trades = pd.read_csv("output/backtest/v2_trades_20260404_230027.csv")
trades['is_win'] = trades['pnl'] > 0
trades['position_mult'] = trades['dynamic_position_mult']  # 需要回测引擎输出此字段

# 核心检验：连赢N笔后第N+1笔的胜率
results = []
for n in range(2, 6):
    streak_starts = []
    for i in range(n, len(trades)):
        if all(trades['is_win'].iloc[i-n:i]):
            streak_starts.append(i)
    if streak_starts:
        next_win_rate = trades['is_win'].iloc[streak_starts].mean()
        results.append({
            'after_win_streak_n': n,
            'count': len(streak_starts),
            'next_win_rate': next_win_rate,
            'vs_baseline': next_win_rate - trades['is_win'].mean()
        })

df = pd.DataFrame(results)
print("连赢N笔后第N+1笔的胜率:")
print(df.to_string())

# 关键判断：
# 如果 next_win_rate 各行与 baseline 82.5% 差距 < 2%，
# 则动态仓位没有真实 alpha，+7% 是历史偶然
```

**如果检验失败（连赢后胜率无显著提升），动态仓位必须禁用**：

```
+7.02% 的实际来源将是：
  在历史上碰巧连赢的时间段（行情顺风）放大了仓位
  这在未来行情中不可重现
  实盘中可能在不应该加仓时加仓，造成超预期亏损
```

### 1.3 信号类型独立 TP 的证伪

报告已承认信号类型独立 TP 贡献约 +0.02%（统计噪声），原因是 flip_bullish 仅 65 笔。

```
需要多少样本才能验证 flip_bullish 独立 TP 有效？

假设效果：flip_bullish 均盈从 $18 → $24（+33%）
假设效果量: d = 0.33
Power = 80%, α = 0.05 的所需样本量:
  n = (z_α/2 + z_β)² / d² × 2 = (1.96 + 0.84)² / 0.33² × 2 ≈ 145 笔

当前 30 天仅 65 笔 flip_bullish，需要 145 笔才能以 80% 功效检验到效果。
等效需要: 65笔/30天 = 2.17笔/天，达到145笔需要约 67 天。
```

**结论**：flip_bullish 独立 TP 的有效性需要 **60~90 天回测数据**才能确认，当前结果不可信。

### 1.4 样本外验证缺失

**最严重的问题**：所有优化（v1.1 → FINAL → v3.0 → v4.0）全部在同一个 30 天窗口（2026-03-05 ~ 2026-04-04）上完成。

```
迭代次数统计（本文档系列）:
  v1.1:     1 次回测
  6项优化:  1 次回测
  v3.0 系列: 3 次（a/b/c）
  FINAL:    3 次消融
  v4.0 系列: 3 次（full/noTP/noDyn）

合计: 约 11 次在同一数据窗口上的迭代

多重检验校正 (Bonferroni):
  α = 0.05 / 11 = 0.0045
  有效显著性阈值提高到 0.5% 而非 5%

这意味着：在没有样本外验证的情况下，
当前 v4.0 比 v1.1 仅高出 +1.91%（50.57% - 48.66%）
在 11 次迭代的多重检验校正下，这个差距几乎不显著。
```

### 行动 4：K 线内入场延迟（架构升级，Week 2）

这是 v4.0 路线图中**唯一未实施且风险最低**的架构升级项。

它的特殊性在于：**不依赖历史数据拟合**，而是基于市场微结构原理（K 线开盘初期价格噪音最大）。因此，它不存在过拟合风险，只有"有效/无效"两种结果。

**实施条件**：在行动 1~3 完成之前可以并行开发代码，但**不要合并进当前回测**，避免与动态仓位系统的交互效应干扰验证。

```python
# scripts/backtest_macd_v2.py
# 新增入场延迟模拟（独立测试，不与动态仓位混合）

def simulate_delayed_entry(signal, bar_ohlcv, config) -> float:
    """
    返回模拟的实际入场价格
    原理：等待K线前30%过去后，用更接近"真实"的价格入场
    """
    if not config.get("entry_delay_enabled", False):
        return signal.entry_price

    bar_progress = config.get("bar_wait_ratio", 0.30)

    # 模拟等待后的入场价：用加权平均近似
    # 开盘价权重(1-bar_progress) + 收盘价权重(bar_progress)
    simulated = (signal.entry_price * (1 - bar_progress) +
                 bar_ohlcv['close'] * bar_progress)

    # 保守：入场价不能比原始价格更差（只能更好或持平）
    if signal.direction == "long":
        return min(signal.entry_price, simulated)
    else:
        return max(signal.entry_price, simulated)
```

**单独验证标准**：

```
必须在 v3.0b 基线（不含动态仓位）上单独测试：

  [Test-Entry-Delay-A] 仅 flip 信号延迟 0.1% passive limit
  [Test-Entry-Delay-B] 所有信号等待 K 线前 30% 后入场
  [Test-Entry-Delay-C] 组合（flip 用 limit，trend 用时间延迟）

接受条件:
  intrabar 止损率从 76.8% 下降至 ≤ 65%
  平均亏损从 -$36 改善至 ≤ -$32
  胜率不下降（入场延迟不应影响信号质量）
  
独立测试原因:
  与动态仓位混合测试时，入场延迟的真实贡献被遮蔽（已验证：混合后贡献≈0）
```
