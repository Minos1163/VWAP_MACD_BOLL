# 策略优化建议报告

**基于日志窗口**：`2026-03-25 08:30 UTC` ～ `2026-03-26 06:45 UTC`  
**报告生成时间**：`2026-03-26 16:36 +08`  
**问题定性**：开仓过载 + 风控机制待优化

---

## 一、核心问题诊断

### 1.1 开仓侧：三层堆积结构

当前开仓失败不是单一原因导致，而是三层依次拦截形成"漏斗式堆积"：

```
原始候选信号（161次尝试）
        │
        ▼
【第一层】3/3容量门控拦截      → 103次（63.98%）
        │
        ▼
【第二层】AI终审全部拒绝        → 29次（18.01%）
        │
        ▼
【第三层】实际执行              → BUY=2 / SELL=27（全为空头）
```

**关键结论**：超过 82% 的开仓尝试被拦截，根因是"高频候选信号 × 槽位瓶颈"共同作用，而非单纯信号质量问题。

### 1.2 风控侧：CIRCUIT_EXIT 触发路径合理，但减仓比例固化

- `CIRCUIT_EXIT` 共触发 3 次（`ALGOUSDT×2`、`ICPUSDT×1`），触发率不高，机制基本正常。
- 存在"降级为 REDUCE（减仓 35%）"逻辑，具有软化能力。
- **问题**：35% 减仓比例对所有品种统一适用，未区分高/低波动资产，对高波动币种（如 ALGO）可能力度不足。

### 1.3 AI 终审：全窗口拒绝，说明本地评分体系与 AI gate 存在系统性偏差

- 29 次 AI 终审请求，100% 给出 `entry_score < 0.080 (0.000)`。
- 分数始终为 `0.000`，接近"哑火"状态，不像正常波动的评分分布。
- 需优先排查：评分特征是否正常传入 AI gate，或 AI gate 本身的阈值是否已失配。

## 三、具体优化建议

### 3.1 P0：排查并修复 AI 终审评分异常

**现象**：`entry_score` 全部为 `0.000`，非正常评分分布。

**排查步骤**：

1. 检查特征向量是否在 AI gate 调用前发生截断或 NaN 填充。
2. 确认 `src/app/fund_flow_bot.py:1508-1514` 的 `final_min_score` 与特征归一化范围是否匹配。
3. 对比历史窗口（非本次）AI 评分分布，确认是否为近期引入的代码变更导致。

**临时措施**（排查期间）：

- 将 AI 终审设为"旁路记录模式"，即记录评分但不拦截，避免因 AI gate 异常完全封堵开仓。
- 日志新增 `ai_score_raw` 字段，便于分段调试。

---

### 3.2 P1：治理 3/3 容量拥堵

**推荐采用"方案B + 动态节流补丁"的组合方式**，而非直接降低槽位。

#### 3.2.1 方案 B 参数调整（平衡型）

| 参数路径 | 当前值 | 建议值 | 调整依据 |
|----------|--------|--------|----------|
| `fund_flow.engine_params.TREND.short_open_threshold` | `0.08` | `0.09` | 空头信号占比过高（93.1%），略提门槛可过滤低质空头 |
| `fund_flow.macd_mtf_strategy_v2.entry_filters.min_vwap_score_for_entry` | `0.12` | `0.13` | 在不大幅影响多头的前提下收紧 VWAP 过滤 |
| `fund_flow.ai_review.final_min_score` | `0.08` | `0.09` | 配合 AI 评分修复后同步微调，不宜单独先改 |
| `risk.conflict_protection.directional_eval_interval_seconds` | `60s` | `120s` | 减少高频风控抖动，降低同一持仓反复触发 REDUCE |

#### 3.2.2 动态候选节流补丁（新增逻辑）

当连续 **≥3 个周期** 均发生 `3/3` 拦截时，触发"拥堵节流模式"：

```
拥堵节流模式（临时，持续至拥堵消退）：
  - open_candidates 仅保留 score 最高的 Top-1 候选进入执行
  - 临时将 short_open_threshold 上浮 +0.01
  - 每 2 个周期重新评估是否退出节流模式
```

此方案无需修改长期阈值，可快速缓解堆积，同时保留高分信号的执行权。

#### 3.2.3 不建议直接执行方案 A（3→2 槽位）的原因

- 槽位从 3 降到 2，意味着最多同时持有 2 个仓位，极端行情下可能影响对冲能力。
- 当前问题根因是"候选供给过多"，减槽位治标不治本，会把拥堵率从 57.8% 推高到更高。
- 建议先实施 B 方案观察 48h，若拥堵率降至 30% 以下，则本次优化达标。

---

### 3.3 P2：CIRCUIT_EXIT 减仓比例动态化

**当前问题**：对所有品种统一减仓 35%，高波动品种（如 ALGO、ICP）在价格快速走坏时 35% 可能远不够。

**建议方案**：按品种波动率分级设置减仓比例。

```
波动率分级标准（建议以过去 24H ATR/价格 作为分级依据）：

  低波动（ATR/Price < 0.02）：REDUCE 比例 = 30%
  中波动（ATR/Price 0.02~0.05）：REDUCE 比例 = 50%（当前 ALGO/ICP 区间）
  高波动（ATR/Price > 0.05）：REDUCE 比例 = 70%，或直接跳过 REDUCE 直接 CIRCUIT_EXIT
```

**代码定位**：`src/app/fund_flow_bot.py:7833-7860`（软化条件判断处）

**过渡期保守方案**：若动态化改造成本较高，可先将全品种统一比例从 35% 上调至 **50%**，作为过渡。

---

### 3.4 P3：空多方向失衡治理

**现象**：`SELL=27, BUY=2`，空头信号占比 93.1%，多头信号近乎消失。

**可能原因**（需逐一排查）：

1. 当前市场处于整体下行趋势，空头信号本就占优（市场结构问题，不需修改）。
2. `long_open_threshold` 相对 `short_open_threshold` 过高，导致多头信号被大量过滤（参数问题）。
3. VWAP 评分逻辑对多头更严苛（逻辑设计问题）。

**建议**：

- 输出近 7 天的多空信号比例曲线，判断是否近期才出现偏空。
- 若确认为参数问题，将 `long_open_threshold` 与 `short_open_threshold` 的差值从当前水平收窄（方向平衡）。
- 不建议在未排查原因前强行调整，避免在真实下行趋势中强开多头。

## 六、专家组讨论议题

1. **AI 终审评分全零**：是数据管道问题还是模型退化？是否需要紧急回滚至上一版 AI gate？
2. **3/3 拥堵率 57.8%**：在市场正常波动周期内该值是否属于系统性问题，还是本窗口行情特殊导致？
3. **CIRCUIT_EXIT 软化机制**：高波动品种（波动率 > 5% 日内）是否应直接跳过 REDUCE，强制全平更安全？
4. **多空失衡**：是否叠加"多头信号频次下限"机制，避免策略在特定行情下完全变为单向空头策略？
